# 0.2.8: agents you can trust, built faster

*Draft, written at freeze on 9 November 2026 for the release page. Fill in
the date, the candidate and the gate's records when the tag is cut, and drop
any known issue that's closed by then. The release page puts GitHub's
generated list of PRs under it ([releasing, step 8](../releasing.md#staging-a-candidate)).*

0.2.7 let an AI agent read your cluster. 0.2.8 lets one change it, without
handing it the keys. An agent can't write anything itself any more: it
proposes, the cluster works out what the change would touch and how to undo
it, and a person (or a policy you wrote) says yes. And if two agents and a
person all reach for the same app at once? Leases sort that out, and people
win.

The other half of 0.2.8 you won't see, but you'll feel it in how soon 0.2.9
and 0.3.0 arrive: our own CI and release loop got shorter.

0.2.8 changes the cluster formats (protocol 58, state 74), so it needs a
fresh cluster. A 0.2.7 cluster can't roll onto it in place
([compatibility before 1.0.0](https://github.com/reliaburger/reliaburger/blob/main/docs/releasing.md#compatibility-before-100)).

## Agents that propose, and people who decide

- **Proposals you can undo.** `relish agent propose` asks for an `apply`,
  `scale`, `rollback`, `stop` or `delete`. The cluster writes the summary,
  the diff, the blast radius and the exact undo command, and holds it until
  someone runs `relish proposal approve`. Approving and applying are one
  Raft entry, and a proposal whose apps changed in the meantime fails as
  `stale` rather than overwrite someone's work. `relish undo` puts an applied
  proposal back for 24 hours, if nothing has touched its apps since
  ([#1682](https://github.com/reliaburger/reliaburger/issues/1682)).
- **Agent tokens.** `relish token create --agent` makes a token that can
  propose changes but can't make any directly.
- **Guardrails in policy.** A policy with `applies_to = "proposals"` judges
  the change itself. It can refuse a proposal, or with `action = "approve"`
  approve one without a person, but never one that can't be undone exactly.
  `relish policy test --proposal` tries your guardrails offline.
- **Leases between agents.** An agent takes a short lease on an app or a
  namespace before it changes it, and anyone else's change to that app is
  refused as `lease_held`, naming who holds it and why. A person's own
  `apply`, `deploy`, `stop`, `delete`, `rollback` or `release` stops at the
  lease too, and `--break-lease` takes it over, on the record. `relish lease`
  lists, takes, renews, releases and breaks them; `relish agent context`
  shows every one
  ([#1686](https://github.com/reliaburger/reliaburger/issues/1686)).
- **MCP without admin credentials.** From an admin context, `relish mcp`
  makes a read-only token of its own, keeps it, renews it and sends that
  instead. `relish mcp --propose` adds the proposing and lease tools, with a
  deployer agent token confined to `--namespace`
  ([#1730](https://github.com/reliaburger/reliaburger/issues/1730)).

## Asking the cluster why

- **`relish verify`** (and `relish agent verify`) checks every node's `bun`
  and the `relish` you're running against the published release, byte for
  byte, by SHA-256 and the release signature, and that every node runs the
  same version. It exits `0` when verified, `1` on a mismatch and `3` when it
  can't tell. `--metadata` and `--artefacts` work on an air-gapped cluster
  ([#1689](https://github.com/reliaburger/reliaburger/issues/1689)).
- **Decisions that explain themselves.** Placement, restart and deploy
  refusal now record the rule they followed and its evidence where they're
  made. `relish agent explain --placement`, `--restart` and `--refusal` read
  it back with the code that decided it, and `relish timeline` (`relish agent
  timeline` for agents) merges events, the audit log and deploys over a
  window you name
  ([#1685](https://github.com/reliaburger/reliaburger/issues/1685)).
- **The whole cluster on one screen.** `relish status` gives a verdict
  (`HEALTHY`, `DEGRADED` or `DOWN`), then one line per part of the cluster:
  nodes, council, gossip, versions, capacity, real usage, apps, jobs, log
  freshness, faults, alerts and `wtf`'s findings, each line that needs
  attention ending in the command to run next. `--check` sets the exit code
  from the verdict. The new `relish apps` lists apps, problems first, and
  `relish nodes` gains version, usage and allocation. The terminal UI, the
  web dashboard and `relish agent context` read the same summary
  ([#1777](https://github.com/reliaburger/reliaburger/issues/1777)).

## Testing your own agent

- **`relish gym run`** deploys the gym's apps into a staging namespace you
  name, breaks them in known ways (bad deploys, a prompt injection, Smoker
  pauses and kills), runs your agent with a read-only token scoped to that
  namespace, scores it, and removes everything it made, Ctrl-C included. It
  writes `report.md` and `report.json` for whoever reviews your agent's
  security ([#1683](https://github.com/reliaburger/reliaburger/issues/1683)).
- **`relish agent patch apply`** applies a unified diff to a patch
  workspace, matching each hunk by its lines rather than its header's
  counts, all or nothing
  ([#1691](https://github.com/reliaburger/reliaburger/issues/1691)).
- **The source digest** of the build inputs is in `candidate.json` and every
  agent envelope, so an agent can tell which exact source a node runs
  ([#1694](https://github.com/reliaburger/reliaburger/issues/1694)).
- **MCP Bundles.** Every release carries a `.mcpb` bundle of `relish mcp`
  per platform, with an Ed25519 `.sig` beside it, and every page of the
  website has "Copy as Markdown" and "Open in Claude" buttons
  ([#1695](https://github.com/reliaburger/reliaburger/issues/1695)).

## Fixes

- A Smoker `pause` of a process-runtime instance on macOS no longer leaves it
  `runtime_unknown` for good, and a delete afterwards stops it
  ([#1772](https://github.com/reliaburger/reliaburger/issues/1772)).
- `brew install reliaburger/tap/relish` works on older Command Line Tools:
  the formula has bottles now
  ([#1712](https://github.com/reliaburger/reliaburger/issues/1712)).
- Redacting a report twice can no longer expose URL credentials that the
  first pass had hidden behind a `key=value` redaction
  ([#1717](https://github.com/reliaburger/reliaburger/issues/1717)).
- Nine flake reports are fixed, each with its cause found first: #1527,
  #1620, #1625, #1641, #1702, #1711, #1726, #1738 and #1748. One was a
  laptop asleep mid-test, not the product; three were one bug, every patch
  test workspace sharing one `.git/info/exclude`.

## Changes that may break a script

- `relish status` no longer lists instances. Use `relish apps --instances`,
  or `relish apps NAME` for one app's.
- `relish agent context` has a `data.status` section (the verdict, the lines
  and the summary) instead of `data.faults`, `data.alerts` and `data.apps`.
- `relish agent guide`'s default budget is 80 KiB, and `relish agent schema`
  has 40 KiB of its own; every other agent command keeps 24 KiB.

## Built faster

Our side of the loop. macOS CI builds and tests only `relish`, since Bun
runs on Linux (#1720). A candidate build waits for `main`'s CI run on the
same commit instead of repeating it (#1722). Train PRs run doctests in a
job of their own and write coverage once (#1723). Stale Actions caches are
trimmed every night, and `make ci` runs its quick checks first (#1724).
There's a plan for splitting the crate into `relish`, `bun` and a shared
crate, to run after 0.3.0 (#1725), and a concept budget that fails a PR
which grows the number of resource kinds, commands or flags without saying
why (part of #1681).

## Known issues

Still open in the 0.2.8 milestone on 9 November 2026:

- **Bun's memory over a long, busy day.**
  [#1417](https://github.com/reliaburger/reliaburger/issues/1417): Bun's
  memory grows for the whole of a 24-hour run at 20,000 jobs a second. 0.2.8
  breaks it down by kind in the soaks; whether it's a leak or a check to
  correct isn't settled.
- **A late agent-loop turn.**
  [#1707](https://github.com/reliaburger/reliaburger/issues/1707): 0.2.7's
  8-hour final saw one 1,215 ms turn against the 1 s budget. 0.2.8 removes
  one plausible cause and adds a guard test, but it isn't proven fixed.
- **What proposals and leases don't do yet.** A proposal can't `restart` an
  app, its blast radius doesn't forecast where the scheduler will put new
  instances, and the dashboard has no Proposals page
  ([#1682](https://github.com/reliaburger/reliaburger/issues/1682)). There
  are no MCP lease tools yet, and the gym has no two-agents scenario
  ([#1686](https://github.com/reliaburger/reliaburger/issues/1686)).
- **Not in the MCP Registry yet.**
  [#1695](https://github.com/reliaburger/reliaburger/issues/1695): the
  bundles ship, but the listing needs the maintainer to publish it. MCP
  clients show the bundle as unsigned until Apple notarisation is set up.
- **One open flake.**
  [#1794](https://github.com/reliaburger/reliaburger/issues/1794): a
  `stop_hooks` test once saw the workload's signal with no record of its
  pre-stop hook.
