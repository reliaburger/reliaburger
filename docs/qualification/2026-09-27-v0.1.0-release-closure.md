# 0.1.0 release closure

25–27 September 2026. A record of the final push to 0.1.0: every pull request
from [#196] onwards, the bug each one fixed, why it happened and how we fixed it,
and how each qualification run went. It's written for someone who wasn't
there. The per-run evidence lives in the records it links; this page is the map.

## Summary

### The gate

0.1.0 ships when the four acceptance gates in
[progress.md](../progress.md#acceptance-and-release-gates) are closed:

| Gate | What it asks | State on 27 Sep |
|---|---|---|
| V01 | The complete live three-node catalogue on independent runc nodes | Open |
| V02 | Sustained TLS, storage, restart and upgrade recovery on the release candidate | Open: one fast-tier failure on d149f52 (a test-runner budget, [#251]); final tier pending on candidate 5 |
| V03 | Publish and install the exact signed candidate | Staged install qualified on Apple silicon ([record](2026-09-25-staged-install-apple-silicon.md)); publication open |
| V04 | Repeated cold installs on the advertised host matrix | Apple silicon done (125–126 s); Intel macOS and Linux open |

Most of this push was V02. Its [plan](../plans/2026-09-25-v02-sustained.md)
has four lanes: A, the sustained soak of a staged candidate on a three-node
quickstart cluster (`scripts/release/qualify-sustained.sh`); B and C, crash and
power-cut fixtures on disposable VMs; D, the `v02-loops` Actions lane. Lane A
became two tiers on 26 September ([#217]):

- **Fast tier** (`--tier fast`): the compressed schedule for 90 minutes. Every
  fault kind, every special and both upgrade-walk variants run in cycles 0–3.
  Run after each round of fixes. A fast run never claims acceptance.
- **Final tier** (`--tier final`): the full schedule for 8 hours, once, on the
  final candidate. Only a clean final run with the candidate digest checked
  says "the V02 gate passes".

A product fix found in the final run means a new candidate, a fresh fast run
and then a fresh final run.

### What "done" means

- A clean fast tier, then a clean 8-hour final tier, on the same staged
  candidate, recorded under `docs/qualification/`.
- Every failure row in those records closed with a cause and a fix or a
  disposition, and the Known flakes register in
  [progress.md](../progress.md#known-flakes) up to date.
- The `v02-loops` lane run and its bounds recorded (still open).
- V01, V03 and V04 closed as above. Only the maintainer tags and promotes.

## Themes and lessons

- **Only a real cluster found the races.** None of the product bugs from the
  dry runs onwards (the retiring adoption, unsynced image unpack, the withdrawal
  receipt, the endpoint catalogue after a leader change, the deploy wedge) was
  caught by the portable, cluster or upgrade suites. In-process clusters
  re-point reporters before the first catalogue tick; a quickstart cluster
  with real systemd, power cuts and restarts doesn't.
- **Fsync is a promise, not a default.** Three durability bugs ([#199],
  [#202], [#203]) had the same shape: a marker or checkpoint said "done" before
  the data was on disk or mounted. The power-cut fixtures found the first in
  four cuts out of four.
- **Test-runner budgets drift from product constants.** The runner's 30 s
  cleanup wait was right until [#237] raised the product's retirement bound to
  60 s ([#251]). Budgets now derive from the product's own constants.
- **The log view isn't the data.** Seventeen of the 12-hour run's 55 failures
  looked like data loss and were log ordering ([#224], [#235]). The record now
  says `*-log-order`, and the writer's file and Redis's counter decide loss
  ([#221], [#238], [#242]).
- **Relay and membership need to remember the dead.** Gossip's published view
  means "worth talking to". A fault clear to a node gossip has declared dead
  needs a different table ([#226], [#244]), and an upgrade plan needs the
  address a node advertised, not a guess ([#230]).
- **Followers must forward.** Workload CSRs ([#204]) and upgrade control calls
  ([#250]) assumed the leader; apply, stop and delete already forwarded.
- **The harness is a product too.** Ten of the PRs fixed the harness or its
  checker, and several (the countersignature, the rollback wait, restart
  expectations) were races of their own.
- **Squash merges hid a semantic conflict.** [#232] and [#236] each passed CI,
  but squash-merged together they left neither fixture trapping SIGTERM and
  broke `main`'s lint ([#239]). From [#239] onwards PRs land as merge commits,
  so `git log --first-parent main` shows one commit per PR and the branch
  history stays intact.
- **The flakes register earned its keep.** Every flake got a row the same day
  with symptom, cause and fix ([progress.md](../progress.md#known-flakes)). Two
  rows had to be revisited when a later fix changed the premise ([#228], [#251]).
- **Fast feedback beats long runs, until it doesn't.** The 12-hour run showed
  its log-order, `relish test` and upgrade-refusal failures within the first
  hour, but the collector leak took nearly five. Hence two tiers ([#217]).
