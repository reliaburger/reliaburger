# Train PR timings before and after #1744, 9 November 2026

How long a pull request into a merge train takes in CI, before and after
[#1744](https://github.com/reliaburger/reliaburger/pull/1744). That change
moved the doctests and the nightly-signing key test off portable Linux and
wrote the coverage report once, for
[#1723](https://github.com/reliaburger/reliaburger/issues/1723): "about 28
min to about 19". #1744 measured its own run and one more; this record
measures every green train run on GitHub. The plan is
[2026-11-06-plan-faster-feedback.md](../plans/2026-11-06-plan-faster-feedback.md).

## Result

On the light path, which most train PRs take, the CI run takes a median of
**19.5 minutes without queueing**, against 30.0 on release-0-2-8 before
#1744 and 36.7 on release-0-2-7's train. Portable Linux itself takes 19.2,
against 29.7 and 36.3. **The run-time target is met.**

**What a PR author waits went up, not down:** a median of 74.1 minutes from
push to the last job, against 36.9 before on the same train. All of the
rise is runners: the light runs after #1744 queued for a median of 56.6
minutes, against 7.6 before, and portable Linux waited 26.8 minutes for a
runner against 1.1. The hosted runners were reported short for part of
this period, with merge groups on release-0-2-8 and release-1-3-0 running
alongside, so this record can't say how much of the queue the change
caused. It adds one job
per light run (a median of 11 jobs ran, against 10), which is one more
runner per PR when runners are short.

Light train PRs that also run portable macOS (14 of the 38 after #1744) have
macOS on their critical path, at 39.5 minutes without queueing. #1723
doesn't cover them.

## Method

**Runs.** Every `CI` (`ci.yml`) run created from 1 November whose event is
`pull_request` or `merge_group`, listed on 9 November with

```sh
gh api --paginate "repos/reliaburger/reliaburger/actions/workflows/ci.yml/runs?event=$EVENT&created=>=2026-11-01&per_page=100"
gh pr list --state all --limit 400 --search "created:>=2026-10-28" --json number,headRefName,baseRefName,createdAt,mergedAt
```

A `merge_group` run's train is in its `gh-readonly-queue/<train>/…` branch; a
`pull_request` run's is its PR's base, by head branch. Kept: runs into
`release-0-2-7` or `release-0-2-8` that succeeded at their first attempt and
ran portable Linux. A re-run attempt keeps the first attempt's times for the
jobs it didn't re-run, so it's left out, and so are docs-only runs, where no
Rust job runs. The qualifying runs were created from 4 November 23:55 to
9 November 06:54 UTC: 158 of them.

**Before or after.** By the run's own jobs, not by date: a run that ran
`doctests and feature tests` carries #1744's workflow. A PR branch cut before
#1744 merged keeps the old workflow until it merges the train in.

**Paths.** `light` is the train PR set: no privileged Linux and no macOS.
`light + macOS` also ran portable macOS. `heavy` ran privileged Linux, as
every merge group does and a PR with the `full-ci` label does.

**Times**, from each job's `created_at`, `started_at` and `completed_at`
(`gh api repos/reliaburger/reliaburger/actions/runs/<id>/attempts/1/jobs`):

- **Wall**: the run's `created_at` to its last job's `completed_at`. This
  is what an author waits.
- **Without queueing**: the critical path through `ci.yml`'s `needs`, each
  job taking the time it ran (`started_at` to `completed_at`) and starting
  the moment its needs finished. For a matrix job, the slowest shard counts.
  This is what the run would take if a runner were always free.
- **Queueing**: wall minus the time without queueing.
- **Portable Linux** ran from `started_at` to `completed_at`, and **waited**
  from its `created_at` to its `started_at`.

The scripts beside this record do it:
[`fetch_jobs.py`](2026-11-09-v0.2.8-train-pr-timings/fetch_jobs.py) reads the
two listings and saves each run's jobs,
[`analyse.py`](2026-11-09-v0.2.8-train-pr-timings/analyse.py) prints the
table below, and
[`rows.json`](2026-11-09-v0.2.8-train-pr-timings/rows.json) holds each
run's numbers. As a check, they give #1744's own sample runs the times #1744
reported: 42420054826, portable Linux 32.1; 42418402032, 30.3; 42427001091,
17.0; 42433378924, 19.1.

The middle half of the light runs, without queueing: 32.4–38.0 on
release-0-2-7, 29.0–30.8 on release-0-2-8 before, 18.8–20.7 after. Wall
time's middle half after #1744 is 54.2–98.0, so the queue varies far more
than the run.

Release-0-2-7's portable Linux was slower than release-0-2-8's before
#1744 (36.3 against 29.7) with the same workflow; this record doesn't say
why. The plan's "about 28" came from a sample of runs up to 6 November,
two of them release-0-2-7 train PRs (42119636996, light, and 42132719996,
light + macOS).
