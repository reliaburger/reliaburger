# Laptop qualification, 17 September 2026

Host: Apple M2 Max, Mac14,5, 32 GiB RAM, macOS 26.3.1. Three Lima 2.1.0
Linux aarch64 VMs, each with 2 vCPUs and 2 GiB RAM. Ubuntu 24.04 image dated
20260911; rootful runc; no source mounts. The managed home, Lima state and
download cache did not exist before either fresh run. Ordinary Internet
access was used; bandwidth was not controlled. Local Rust checks ran alongside
the second run, so this is not an isolated performance benchmark.

These runs used **explicit development binaries** already present on the host.
They include tooling/image downloads, VM creation, guest package installation,
enrolment, quorum and sample HTTP verification. They exclude downloading the
native CLI and signed guest release artefacts. They do not qualify the public
`curl` installation command or a signed release.

## Results

| Run | Result | Elapsed |
| --- | --- | --- |
| First empty-home run | Failed at the setup deadline; two guests stalled in PAM session creation | 300.63 s |
| Resume after rebooting the two affected owned guests | Quorum and sample HTTP passed using saved identities/disks | 63.7 s |
| Second empty-home run, with login-service restart during provisioning | Three-node quorum and sample HTTP passed | 241.75 s |

The first guests' journals recorded `pam_systemd(sshd:session): Failed to create
session: Connection timed out`. Lima's first-boot scripts replaced the user
manager during an SSH session. Restarting `systemd-logind` in system provisioning,
after Lima's built-in setup, avoided the stall in the second fresh run.
No host login or SSH configuration was changed.

Second-run command (the managed home was new):

```sh
RELIABURGER_HOME=/tmp/reliaburger-cold-login-fix \
  target/debug/relish setup --quickstart --nodes 3 \
  --api-port 29117 --ingress-port 28080 \
```
