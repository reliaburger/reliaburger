# 0.2.5: Bugs an outside evaluation found

0.2.5 is a patch release. It fixes the product bugs that an external evaluation of 0.2.0 ([#1080](https://github.com/reliaburger/reliaburger/pull/1080), 18 October 2026) found and that are still on `main`, plus a stale log view that 0.2.4's day run found. Each one is something an operator or a script hits in ordinary use. None of them is new in 0.2.4.

The evaluation ran 86 scenarios against a three-node cluster installed from the [Linux servers guide](../linux-servers.md), driving it only from outside, through `relish`, HTTP and the hypervisor. Of its findings, these were checked against `main` at `81375b93` by reading the code on 31 October; the rolling-update outage and GitOps removing hand-applied apps were already fixed (#692, #824). Whether and how the evaluation harness itself joins the pipeline is a separate decision, discussed on #1080.

## Issues

Every issue body is self-contained: what's wrong, where, and what done looks like. Each is one PR into `main`, on a `0-2-5/<topic>` branch, with failing tests first.

| Issue | What | Size | Gate impact |
|---|---|---|---|
| [#1496](https://github.com/reliaburger/reliaburger/issues/1496) | `relish token create` on a follower returns 503 instead of being forwarded to the leader, and a new token is refused for up to about 5 s on the node that made it | Small | None expected |
| [#1497](https://github.com/reliaburger/reliaburger/issues/1497) | Issued certificates have no Authority Key Identifier, so strict verifiers such as Python 3.13 refuse the API | Small | None: existing clusters get it as leaves renew |
| [#1498](https://github.com/reliaburger/reliaburger/issues/1498) | The Kubernetes importer drops an init container's `env` and doesn't report it | Medium | Moves `CURRENT` to 56/73 and touches `src/bun/agent/`: the full gate |
| [#1499](https://github.com/reliaburger/reliaburger/issues/1499) | `relish logs-export --dest` writes on the agent's host, while the CLI and the manual treat the files as local | Small to medium | None expected |
| [#1500](https://github.com/reliaburger/reliaburger/issues/1500) | Deleting an app and applying it again at once can leave the old instances' retirement stuck until Bun restarts | Reproduced in one agent with a real journal; the fix is at deploy admission | Touches the agent loop, so 0.2.5 needs the full gate |
| [#1501](https://github.com/reliaburger/reliaburger/issues/1501) | The `relish audit` table shows no app name for an apply of several apps | Small | None |
| [#1493](https://github.com/reliaburger/reliaburger/issues/1493) | `relish logs --tail` keeps returning the same old lines once an app has logged for a while | Unknown until diagnosed | None expected |

[#1494](https://github.com/reliaburger/reliaburger/pull/1494) also ships in 0.2.5: spare nodes join as learners up to the council cap, the fix from the 0.3.0 train for the secure clusters of two, four or six nodes whose last node restarts forever. It's part of [#1477](https://github.com/reliaburger/reliaburger/issues/1477), not all of it: nodes past the cap still stay outside Raft, and the soaks' three nodes don't exercise this change.

## After the tag

A 12-hour memory run on the published release ([#1417](https://github.com/reliaburger/reliaburger/issues/1417), [#1403](https://github.com/reliaburger/reliaburger/issues/1403), [#1418](https://github.com/reliaburger/reliaburger/issues/1418)), with the Mac to itself. 0.2.5 makes no sustained-rate claim, so the 24-hour day run isn't owed.

## Shared rules

- **Compatibility:** `main` is at 55/72, as 0.2.4 shipped. The first 0.2.5 PR that changes the wire or durable state bumps `CURRENT` once, to 56/73; later ones add a line under the 0.2.5 heading in `src/compatibility.rs`. The 0.3.0 train then goes above 0.2.5 when it merges `main`.
- **Docs:** each PR updates its book chapter, and the manual or design doc where they describe the behaviour, in the same change.
- **Tests:** `make ci` plus the gated target that matches what the PR touches.

## The gate

0.2.5 runs the patch gate unless a PR moves `CURRENT` or touches the agent loop. #1498 does both and #1500's fix touches the loop, so 0.2.5 needs the full gate. `release_tier.py` confirms it at freeze ([a gate scaled to the release](../releasing.md#a-gate-scaled-to-the-release)). Only the maintainer tags and promotes.

## Done when

Every issue above is closed by a merged PR, the gate passes on a candidate built from `main`, and 0.2.5 is promoted.
