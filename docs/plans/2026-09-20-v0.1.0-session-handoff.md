## Decisions already made

These do not need another clarification:

- Pre-release development clusters require fresh state. Later upgrades require
  explicit compatible protocol/state formats. Current formats are protocol 14,
  state 27, OCI intent schema 4, job checkpoint schema 2 and lease schema 5.
- Process workloads must stay in the foreground and retain their children in
  the supervised process group. Detached/daemonising workloads use Linux containers.
- macOS containers use managed Linux VMs. Direct Apple Container selection is
  disabled for 0.1.0; its daemon-operation recovery is deferred under F10. Native
  foreground process mode remains available.
- Unknown ordinary jobs require an explicit rerun. Cron skips missed or uncertain
  firings after a crash; bounded job retries are a separate policy.
- Cleanup needs confirmation. An operator may discharge a disconnected node's
  obligations only after externally stopping/isolating it and permanently
  retiring its identity. Return requires fresh enrolment under a new identity.
- The original development signing key was unavailable. Its replacement public
  identity is committed and the matching `RELIABURGER_RELEASE_KEY` Actions secret
  was configured with explicit user approval. Do not regenerate it or expose the
  private key. No candidate, release tag or public release has been published.

## What is implemented

The ledger contains the full history. These distinctions matter when resuming:

- Production foreground ProcessGrill uses durable generation owners, launch
  inventory, authenticated control and positive descendant retirement. Job/cron
  checkpoints, initialiser ownership and auxiliary exec supervision are wired.
- Owned rootful/rootless Runc adapters exist and have physical recovery tests.
  They retain original specifications, lifecycle claims, command inventories,
  launchers and network helpers. **They remain opt-in.** Production Runc selection
  awaits complete discovery recovery and qualification.
- The persistent kernel loader retains and verifies original maps/links across
  loader death. **Production loading is still ephemeral.** Actual Bun death and
  host reboot remain separate acceptance boundaries.
- Original source/egress ownership is durable. Namespace policy covers jobs and
  portless workloads; destination identities use allocated VIPs. Explicit service
  and rollout retirement check backend withdrawal, destination-grant deletion and
  kernel errors rather than reporting false completion.
- Registry/storage ownership, lease cleanup, permanent node decommission,
  credential renewal, compatibility checks, signed-candidate preservation and
  managed installation are implemented with scoped evidence in the ledger.
