# 0.2.3: Two billion a day

0.2.3 has one headline and a set of follow-ups. The headline is 2B host-job tasks in one real 24-hour day on a three-node cluster (23,148/s sustained, about 7,700/s per node), with 1B as the floor: profile, speed up one node, prove scale-out, run the day and publish it. The follow-ups come from the [CI and test efficiency plan](2026-10-11-ci-and-test-efficiency.md) and from what the 0.2.2 agents found: tests that can't fail, soak verdicts that can pass with checks missing, flakes under local load, and two product gaps. Every issue body is self-contained: why, what, tests to write first and done-when. This plan only fixes the order and the shared rules.

## The train

- **Branch:** `release-0-2-3`, cut from the tip of `release-0-2-2` on 20 October 2026, while 0.2.1 was still being qualified and 0.2.2 was waiting on it.
- **Gate PR:** a draft into `release-0-2-2`, so its diff shows only 0.2.3. It retargets to `main` once 0.2.2 has merged. It carries a `Fixes #N` line for every issue here except #1053, because closing keywords only fire on merge into `main`.
- **Each issue is one PR into `release-0-2-3`.** Whenever `release-0-2-2` moves, it's merged into the train, never rebased.
- **Version:** the crate stays at whatever `release-0-2-2` has until 0.2.2 ships.
- **Compatibility:** no bump when the train opens. The first 0.2.3 PR that changes the wire or durable state bumps `CURRENT` once, above 0.2.2's 53/70, and later ones add a line under the 0.2.3 heading in `src/compatibility.rs`. The 0.3.0 train then stays above 0.2.3 when it catches up.
