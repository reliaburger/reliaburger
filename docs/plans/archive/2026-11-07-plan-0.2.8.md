# 0.2.8: agents you can trust, built faster

7 November 2026. The scope the maintainer chose at 0.2.8's brainstorm
([#1673](https://github.com/reliaburger/reliaburger/issues/1673)), the order
we'll build it in, and what proves each piece. Status lives in the
[0.2.8 milestone](https://github.com/reliaburger/reliaburger/milestone/30);
this plan doesn't track it.

0.2.8 has two halves, merged into one release (maintainer decision, 6 November
2026):

- **Built faster:** our own loop of building, testing, merging and releasing
  gets shorter, so every release after it ships sooner. The measurements are
  in [the faster-feedback plan](../2026-11-06-plan-faster-feedback.md).
- **Agents you can trust:** 0.2.7 made Reliaburger easy for an AI agent to
  read and debug. 0.2.8 makes it safe to let one act, and makes the evidence
  for that public.

It releases when this scope is built and its gate passes. Until 1.0 there
are no target dates (maintainer decision, 6 November 2026).

## Built faster

| Issue | Change | How we know it worked |
|---|---|---|
| [#1720](https://github.com/reliaburger/reliaburger/issues/1720) | macOS CI builds and tests only `relish`; Bun is tested on Linux, where it runs | The macOS job's wall time on real train PRs, against the 66-minute median. #1699 measured 31 minutes from a cold cache |
| [#1721](https://github.com/reliaburger/reliaburger/issues/1721) | Nightly qualification on the Studio, every night, on the train tip | At least one green night that `freeze-check` accepts, so the gate after freeze is the staged installs alone |
| [#1722](https://github.com/reliaburger/reliaburger/issues/1722) | A candidate build reuses `main`'s CI run | A candidate on a commit with green CI goes straight to packaging |
| [#1723](https://github.com/reliaburger/reliaburger/issues/1723) | Faster train PRs: doctests and the nightly-signing test in parallel, coverage written once | Train PR wall time, about 28 minutes before, about 19 targeted |
| [#1724](https://github.com/reliaburger/reliaburger/issues/1724) | Trimmed caches, the quick checks first, and the parallel-agent lessons written down | The cache size; CLAUDE.md and the agent briefs |
| [#1725](https://github.com/reliaburger/reliaburger/issues/1725) | A plan to split the crate into `relish`, `bun` and shared types | The plan merged. The split itself runs right after 0.3.0 merges, so it doesn't fight 0.3.0's open train |

Merge-queue groups went from 4 to 8 on 7 November, a ruleset change with
nothing to build.

Nightly qualification changes how the Studio is used. Agents and builds
run there by day only, because load fakes soak failures. A long one-off run,
such as a 24-hour memory run, takes a night off from the nightlies. The
maintainer chose to try it and see how it works out in practice, so the
first nights' findings go into [releasing.md](../../releasing.md).

## Agents you can trust

Each idea gets a short design note in this plan's issue before code, is
tested in the agent gym (`scripts/gym/`), and is shown on the site with real
recordings and measured numbers, never mock-ups.

| Issue | Idea |
|---|---|
| [#1689](https://github.com/reliaburger/reliaburger/issues/1689) | **Verify this cluster in one command.** Every node's binaries match the release's signatures and attestations, versions agree, nothing has drifted. Read-only, with the agent output contract |
| [#1685](https://github.com/reliaburger/reliaburger/issues/1685) | **Ask the cluster why.** Why the scheduler placed an instance there, why something restarted, why a deploy was refused, each with its rule and evidence; and the incident timeline of what changed before a failure |
| [#1683](https://github.com/reliaburger/reliaburger/issues/1683) | **The gym for users.** `relish gym run` tests a team's own agent on their own cluster's staging namespace with known faults, and scores diagnosis and safety |
| [#1687](https://github.com/reliaburger/reliaburger/issues/1687) | **Built for small local models.** The gym runs with open local models (through Ollama) as well as Claude, the results are published, and budgets are tuned where small context windows struggle. Added at the brainstorm |
| [#1682](https://github.com/reliaburger/reliaburger/issues/1682) | **Agent changes are proposals you can undo.** A plain-language diff and blast radius, approval by a human or a policy, a one-command undo shown before it applies, and guardrails in policy. The headline |
| [#1686](https://github.com/reliaburger/reliaburger/issues/1686) | **Locks between agents,** built with #1682: a short lease before a change, visible in `relish agent context` and the audit log |
| [#1681](https://github.com/reliaburger/reliaburger/issues/1681) | **The whole platform fits in your agent's context.** The concept-budget test now; the measured numbers once the Kubernetes comparison (#1679) has run |
| [#1690](https://github.com/reliaburger/reliaburger/issues/1690) | **The showcase** on the website, the book and the whitepaper, for whatever ships. Last |

The local-model runs and the agent recordings load the host, so on the
Studio they take a slot of their own, like a soak.

## Order

1. **Speed first,** because it shortens everything after it: #1720, #1722,
   #1723 and #1724. They're CI changes and need no quiet host.
2. **Nightlies** from the first free night, after the memory run ends on
   8 November (#1721).
3. **Quick wins:** #1689 and #1707.
4. **In parallel:** #1685, #1683 and #1687.
5. **The headline:** #1682 with #1686.
6. **The showcase** (#1690), then freeze, the gate and the release.

The crate split's plan (#1725) can be written at any point. The split runs
after 0.3.0 merges.

## Who does what

The Mac Studio runs the soaks, the nightlies, the local-model runs and the
recordings, and by day the parallel agents for the larger features. A laptop
session takes the CI changes and the smaller items while the Studio is quiet.
The two share decisions on the issues and through messages. 0.3.0 continues
on the other laptop session in parallel.
