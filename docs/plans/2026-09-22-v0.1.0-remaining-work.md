# Remaining work for 0.1.0 — 22 September 2026

The release is not ready. C34 remains the correctness blocker; V01–V04 are
acceptance gates. The installer, website, signing workflow and control-plane
withdrawal machinery exist. They do not replace end-to-end release qualification.

Completed in the activation session:

- Normal enrolled rootful Runc/eBPF startup recovers consumer ownership before
  adoption. Standalone rootless startup recovers original execution and forwarding.
- Local services use council VIPs. Retirement waits for consumer guards and exact
  runtime release proof; repeated local removal is idempotent.
- Startup retains stopped executions and reserved ports until remote cleanup can
  progress. Discovery polling continues during pending deployments.
- Actual rootful and rootless OCI upgrade, explicit rollback and failed-candidate
  automatic revert preserve the live execution; confirmed cleanup succeeds.
- Three enrolled OCI nodes pass six controlled leader-last node API swaps and final
  remote retirement (76.54s). This fixture uses one isolated Linux host; the full
  independent-host catalogue and rolling-controller acceptance remain V01/V02.
- Protocol 20/state 39/discovery schema 4 are current. Earlier development state
  requires a fresh cluster. Standalone complete host reboot remains qualified.

Validation passes 334 affected native and 340 affected Linux cases, final strict
checks on both, the repaired live CI placement case on both, and physical managed
bpffs startup. Hosted validation of the pushed head remains separate. Exact
evidence is in the session handoff; no local compiler/test pipeline is active.

Producer release/stale-report protection, durable consumer recovery and receipt
retry are implemented. Rootless cluster support remains unqualified: surviving
execution intent alone cannot authorise reuse of an old remotely published host
port after restart. The pending recommendation is standalone rootless and rootful
clusters for 0.1.0; no answer has been assumed.

Working estimate: **roughly 2–4.5 engineering days** if rootless clusters are
explicitly deferred, plus external waits and the 24–48-hour soak. Including rootless
clusters adds roughly 1–2 engineering days. These estimates remain conditional on
final CI and acceptance findings.
V05 dependency review is complete for the current lockfile with dated exceptions.
Optional refactors and explicitly deferred features are not new release blockers.
Fresh pre-release clusters, foreground-only native processes and the managed
Linux VM for macOS containers remain the agreed release scope.
