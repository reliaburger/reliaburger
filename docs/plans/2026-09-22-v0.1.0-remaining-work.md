# Remaining work for 0.1.0

**Updated:** 22 September 2026.

The codebase completion work (C01–C34) is done, and the
[PR #167 review fixes](2026-09-22-pr167-review-fixes.md) are the current
engineering plan. What's left before we can tag 0.1.0 are four acceptance gates.
None of them is new feature work: each one proves, on real hosts, that what we
already built holds up.

## Remaining gates

Estimates are focused engineering effort, including ordinary failure
investigation. One day means about eight hours. Review, CI queues, clean-host
availability and soak time add elapsed time, and new failures can stretch the
ranges.

| Gate | Difficulty | Estimated effort | Done when |
| --- | --- | --- | --- |
| V01: live three-node acceptance | Medium–high | 0.5–1 day | The full supported catalogue, chaos, diagnostics, storage and cleanup matrix passes on three independent Runc nodes. |
| V02: sustained TLS/storage/restart/upgrade qualification | High | 0.5–1 day, plus 24–48 hours running | The release candidate survives sustained failures and recovers; every failure is investigated before acceptance. |
| V03: exact signed release candidate | Medium | 2–4 hours, plus review, merge and CI | Reviewed code and workflows reach `main`; we build once, stage over HTTPS, install and verify those exact bytes; promotion doesn't rebuild. |
| V04: repeated cold laptop installation | Medium–high | 0.5–1.5 days, plus host availability | Clean supported hosts, including Intel macOS, reach a working cluster in under five minutes. |

Working estimate: roughly two to four engineering days, plus external waits and
the 24–48 hour soak.

## Agreed 0.1.0 scope

- **Container clusters** run on rootful Linux Runc with eBPF service discovery.
- **Rootless Runc** is standalone only. Bun refuses to start a rootless node with
  `--cluster`. Rootless clusters are deferred past 0.1.0, not dropped.
- **macOS** runs containers through a managed Linux VM.
- **Native processes** are foreground-only.
- **Clusters are fresh.** 0.1.0 is the first release, so there's no upgrade path
  from development-era state; start a new cluster.

Optional refactors and deferred features aren't release blockers. Dependency
review (V05) is done for the current lockfile, with dated exceptions.
