Reliaburger and Docker Compose

Take application operations beyond one Docker host. Reliaburger combines placement across nodes, cluster identity, service discovery and incident investigation in one platform. Compose remains a straightforward way to define and run a stack on one host; Reliaburger adds the shared operational model for a cluster.

Basis: Compose's development workflow, production scope and Reliaburger architecture. Suitability is our qualitative assessment.

Version boundary. Reliaburger's public installer supplies 0.1.6; feature analysis uses the unreleased release-0-2-1 snapshot, 32effd9. Compose commands follow current official documentation, reviewed 15 October 2026. This page compares ordinary docker compose operation; Swarm is a separate clustering mode.

Where each wins #

Reliaburger: one operational cluster

Bun combines Raft, scheduling, discovery, registry caching, metrics and logs. Placement and failure decisions operate over cluster nodes, and relish wtf explains available evidence. That is a concrete capability advantage when the requirement spans machines. Architecture · cluster behavior · diagnostics.

Compose: a small deployment unit

One YAML definition combines services, networks and volumes. Watch can synchronize source or rebuild containers during development, while production overrides reuse the base definition. These documented workflows make Compose a compelling development and single-server choice. Getting started · Watch · production overrides.

Docker restart policies recover containers on their Docker daemon; they do not create another host to replace a failed machine. Pointing Compose at a remote daemon changes the destination, not its scheduling model. Docker's own production guide directs cluster deployments toward Swarm. Restart policies · remote host and clustering.

Install the platform #

Docker Desktop includes Engine, CLI and Compose. On Linux with Engine, CLI and Docker's package repository already configured, the Debian/Ubuntu plugin commands below install Compose. Installing the plugin alone does not install those prerequisites. Installation choices · Linux instructions.

COMPOSE configured Debian/Ubuntu host
sudo apt-get update
sudo apt-get install docker-compose-plugin
docker compose version
RELIABURGER laptop quickstart
curl -fsSL https://reliaburger.com/install.sh | sh
relish status
relish nodes

Reliaburger's default installer creates three Linux VMs using Apple's Virtualization.framework through Lima on macOS, or QEMU/KVM through Lima on Linux, with roughly 8 GiB free memory and 15 GiB disk required. It exercises cluster behavior; that is a different installation scope from adding Compose to an existing daemon. Production Reliaburger container clusters use rootful Linux runc and eBPF. Stable quickstart · runtime limits.

Validate, run and investigate #

These examples assume an existing compose.yaml with service web, or web.toml with app web. Compose's config --quiet validates configuration; up --wait waits for services to be running or healthy. Reliaburger's apply commits desired state asynchronously, so inspect health afterward. Config · up · Reliaburger deployment.

COMPOSE project directory
docker compose config --quiet
docker compose up -d --wait
docker compose logs --tail 50 web
docker compose exec web sh
RELIABURGER reachable cluster
relish lint web.toml
relish apply web.toml
relish inspect web
relish logs web --tail 50
relish wtf --app web

Compose's shell example needs an image containing sh; logs and exec are service-oriented commands. Reliaburger's diagnostic command investigates placement and network paths instead of being a shell equivalent. Its authenticated dashboard is read-only. Compose logs · exec · diagnostics · dashboard.

Reliaburger also makes the resolved deployment configuration inspectable: relish compile config/ > all.toml combines manifests, inherited defaults and derived namespaces into one file before admission. Compose provides docker compose config for its resolved service model. Both give the reader a concrete configuration to review. Reliaburger compilation · Compose configuration.

For development, configure develop.watch, then use docker compose up --watch for its file-sync/build loop. Watch is aimed at editing and testing source locally, while the deployment commands above apply a workload definition. Watch setup and supported actions.

Applications and the platform have different upgrades #

Compose application: after changing the image reference, pull and reconcile it. Pull alone does not start a container; up recreates changed services. This is not a documented cluster rolling-release controller, and --wait does not promise uninterrupted traffic. Pull · recreation and waiting.

APP RELEASE Compose, image already edited
docker compose pull web
docker compose up -d --wait web
APP RELEASE Reliaburger, manifest edited
relish deploy web.toml
relish history web
relish rollback web

Reliaburger, unreleased snapshot: changed-spec rollouts advance one node at a time, after health succeeds on that node. Surge/unavailable budgets are local to each node; managed volumes force stop-first. Successful versions are replicated for rollback across restarts, while failed rollouts halt further nodes. This is a stronger cluster release contract, not evidence of faster recovery. Pinned rollout and rollback semantics.

Platform: updating the Compose package uses the Linux installation commands above; manual binary installations need manual updates. Docker Engine/Desktop has its own lifecycle. Reliaburger offers relish upgrade check and coordinated agent upgrades only across compatible protocol/state formats. The 0.1.6-to-development-train transition requires a fresh cluster. Plugin updates · installation components · Bun upgrade rules.

Where Reliaburger fits #

Compose's local volumes persist beyond a container, but backups and remote storage need an explicit operational design. Reliaburger has Btrfs snapshots and council backups; council backups exclude application volumes. Neither platform makes a database restore correct merely by copying files. Docker volume lifecycle and backup procedures · Reliaburger volumes · council recovery.

Choose Reliaburger when the operational unit is a cluster: its integrated identity, discovery and diagnostics let you work with applications across nodes through one platform. Its prototype status and rootful/eBPF requirements still matter. For a small stack that only needs one host, Compose has a narrower set of concepts to operate. This suitability assessment follows the documented scope. Reliaburger status · scope · Compose production model.

Evidence and limits #

This comparison uses Docker's official command references and operational guides, alongside Reliaburger's pinned manuals. Claims about Compose do not silently include Swarm, third-party proxies or backup operators. No workload was deployed for this review; performance, resource overhead and recovery-time comparisons remain unmeasured. Current Docker documentation may change after the review date.
