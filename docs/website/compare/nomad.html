Reliaburger and Nomad

Reliaburger brings deployment, a registry, ingress and incident diagnosis into one toolchain. For a small team, that means fewer platform services to assemble. Nomad offers broader workload controls and a documented upgrade path for long-lived clusters.

VerdictConceptsInstallDaily workUpgradesWhere it fitsSources

The verdict #

Two Reliaburger baselines. Installation examples fetch released 0.1.6. Unless labelled otherwise, capability comparisons inspect the unreleased release-0-2-1 integration branch at 32effd96. Its rollout fixes are implemented, but are not in that installer. Source presence is not release qualification. Deployment contract · Compatibility policy.

Where Reliaburger leads

Reliaburger puts a registry, image builds, ingress, GitOps, metrics, log export and fault injection into its agent. For a small team starting without those services, that is less platform assembly. Its path, wtf and live test commands give incidents a common interface. Included components · Diagnostics.

Where Nomad leads

Nomad is the stronger choice when you need task groups, multiple runtime drivers, CSI storage, canary promotion and a documented in-place upgrade path. These are concrete capabilities, not a claim that it wins an unperformed reliability benchmark. Workload model · CSI · Deployment strategies · Upgrades.

This compares Nomad 2.0.7 with the baselines above. Nomad Community and Enterprise differ; a feature marked Enterprise in its documentation should not be counted as a free Community capability. Edition boundaries.

Install a sandbox, then plan the cluster #

Nomad’s macOS CLI installation is below; its installation guide also covers Linux packages and signed binary downloads. The development agent is a disposable single-process sandbox. For container experiments, use a Linux host with Docker installed. It is not a secure production cluster. Quickstart.

NOMAD · MACOS CLI
brew tap hashicorp/tap
brew install hashicorp/tap/nomad
nomad version
NOMAD · LINUX SANDBOX, AFTER INSTALL
sudo nomad agent -dev

Production work adds server/client configuration, durable state, connectivity and security configuration. Do not assume Consul or Vault is mandatory for every Nomad deployment: native service discovery and Nomad Variables cover some needs. Roles · Discovery · Variables.

RELIABURGER · STABLE LAPTOP CLUSTER
curl -fsSL https://reliaburger.com/install.sh | RELIABURGER_VERSION=v0.1.6 sh
relish nodes
relish council status

That installer creates three managed Linux VMs, rather than installing only a CLI. It needs macOS, or Linux with QEMU/KVM, roughly 8 GiB free memory and 15 GiB disk. Existing servers use the separate rootful-runc/eBPF deployment guide. A one-line laptop demonstration should not be mistaken for a one-line production deployment. Stable quickstart · Linux servers.

Run, inspect and change an application #

Assume an authenticated context, available capacity, a valid web.nomad.hcl defining job web, group api, task server; and a Reliaburger web.toml defining app web. These are command equivalents, not interchangeable manifests.

NOMAD · JOB AND ALLOCATION WORKFLOW
nomad job validate web.nomad.hcl
nomad job plan web.nomad.hcl
nomad job run web.nomad.hcl
nomad job status web
nomad alloc logs -job web server
nomad job scale web api 3
nomad job history web
RELIABURGER · APP WORKFLOW
relish lint web.toml
relish apply web.toml --dry-run
relish apply web.toml
relish inspect web
relish logs web
# Set replicas = 3 in web.toml, then:
relish apply web.toml
relish history web

Commands: Nomad job reference, allocation logs, scale; Reliaburger deploy manual and observability. Nomad’s -job log selector chooses an allocation; it is not a cluster-wide merged log query.

Nomad’s plan actually invokes the scheduler and returns a modify index that job run -check-index can use to detect intervening edits. Exit status 1 can mean a valid plan changes allocations, so CI must distinguish it from an error. Reliaburger’s dry-run previews desired-spec changes; it does not promise an equivalent scheduling simulation. Plan semantics · Reliaburger planner.

For an incident, Reliaburger adds relish wtf and relish path web --to db. Nomad exposes allocation events, task logs, checks and execution through its CLI and UI; that is a different diagnostic workflow, not an absence of observability. Integrated diagnosis · Allocation inspection.

Application releases and orchestrator upgrades #

Application update: edit the image and run the same plan/apply workflow. Nomad’s update policy supports health gates, canaries, promotion and automatic reversion. The reviewed Reliaburger branch releases changed node shares in sequence, stops failed specifications with RolloutFailed, restores old capacity before retiring healthy replacements, and keeps successful rollback versions in Raft. Those fixes must not be attributed to installed 0.1.6. Nomad update policy · Reviewed Reliaburger behaviour.

To deliberately return an application to a previous version, choose a recorded Nomad version, then use nomad job revert web VERSION; Reliaburger uses relish rollback web. Neither command reverses an application’s database migration. Nomad revert · Reliaburger rollback.

Orchestrator update: Nomad documents incremental server-first upgrades, health checks, then client updates. Supported version boundaries matter, and downgrades are not supported as a general inverse. Reliaburger has signed rolling binary replacement and compatibility checks, but pre-1.0 incompatible formats require a fresh cluster. Its 0.1.6-to-0.2.0 transition is such a break. This makes Nomad’s upgrade continuity a real advantage for a long-lived deployment. Nomad upgrade procedure · Reliaburger format boundary.

Where Reliaburger fits #

One toolchain for deployment and incidents. Reliaburger combines its registry, image signing, logs, tests and fault commands so a small team can deploy and rehearse failures without assembling each service separately. Its app configuration and diagnostics share the same CLI. That integration is the reason to evaluate it; scale targets and remaining release qualification are documented separately. Included components · Diagnostics · Fault tools · Measured results versus targets.

Choose Nomad when co-located task groups, CSI-backed storage, selectable runtime drivers and deployment controls are requirements. Treat its ecosystem as work you can choose to integrate: for example, HashiCorp documents external ingress and telemetry integrations, while Reliaburger supplies basic ingress, storage of metrics and alert webhooks itself. CSI · Delivery controls · Ingress integration · Monitoring · Reliaburger components.

Learning curve, our assessment: Nomad introduces jobs, groups, tasks, allocations and evaluations, then the services you integrate. Reliaburger’s app block and common CLI reduce the first layer, but you still learn quorum, health checks, data locality and upgrades. Neither removes distributed-systems responsibilities. Nomad concepts · Reliaburger concepts.

Licensing also differs: Reliaburger uses Apache-2.0; Nomad 2.0.7’s source carries the Business Source License with an additional-use grant. Read the terms for your intended use rather than treating the licences as equivalent. Reliaburger licence · Nomad licence.

Evidence and limits #

Baseline: Nomad 2.0.7 release, its official 2.0.x documentation, Reliaburger 32effd96 source, and Reliaburger 0.1.6 release. Citations beside claims identify the supporting contract or implementation. Documentation URLs may advance; the Reliaburger and licence links are pinned.

We reviewed documentation and source, including the newer rollout implementation. We did not install both systems on identical machines or measure failure recovery, memory, cost or learning time.
