APPLICATION DELIVERY / COOLIFY

Reliaburger and Coolify

Deploy and diagnose a cluster through one command line. Reliaburger brings scheduling, identity, discovery, logs and incident tools into its node agent, so the same application names carry from deployment into investigation. Coolify offers a browser-led path from Git repository to a public web application.

Basis: Coolify deployment workflow and Reliaburger architecture.

Which Reliaburger. The public installer installs 0.2.2, and the feature analysis below describes that release, re-checked on 21 October 2026. Coolify is pinned to 4.4.6, with current official documentation for workflows.

Where each wins #

Reliaburger: the integrated cluster

The Bun node agent bundles Raft, scheduling, registry caching, network discovery, metrics and logs. Its CLI adds network-path diagnosis and controlled fault injection. Operators get a shared application model across these tasks and fewer separately operated platform components. Architecture · diagnostics · chaos.

Coolify: the application product

Git sources, preview environments, automatic public TLS and engine-aware database backups form an immediately useful delivery workflow. These are concrete advantages over assembling equivalent workflows around Reliaburger. Sources · previews · TLS · backups.

Coolify's additional deployment servers are standalone destinations: an external load balancer and shared application state remain your responsibility. Its documented multi-server application flow excludes Compose applications and resources with persistent storage. This is materially different from Reliaburger scheduling replicas within one cluster. Coolify limits · Reliaburger cluster model.

Run the Coolify script as root on a supported Linux server. Open the printed dashboard URL, create the administrator and save the generated installation secrets. Its documented minimum is 2 CPU cores, 2 GB RAM and 10 GB disk, before application capacity. Official installation.

Reliaburger's default install builds a three-node Linux VM cluster on Apple silicon macOS, or Linux with QEMU/KVM, requiring roughly 8 GiB free memory and 15 GiB disk. That is a laptop demonstration with three nodes, so comparing these requirements as equivalent overhead would be misleading. Production container clusters require rootful Linux runc and eBPF. Deploy, inspect and recover #

Coolify's browser workflow

  1. Connect a public repository, deploy key or GitHub App; choose the build method and configure the application. Source access.
  2. Select Deploy, then inspect the queued operation under Deployment Logs. Set a domain and redeploy to activate its route; HTTPS uses the configured proxy's certificate automation. Deployments · domains.
  3. Enable Preview Deployments with separate preview variables, then verify creation and cleanup against repository events. A database's Backups page separately configures scheduled dumps and optional S3 storage. Previews · database backups.

Reliaburger's command workflow

With an authored web.toml containing app.web and a reachable cluster, these commands validate, apply, inspect and diagnose it. apply accepting cluster state is distinct from every replica becoming healthy. Deployment contract · diagnostics.

RELIABURGER existing web.toml
relish lint web.toml
relish apply web.toml
relish inspect web
relish logs web
relish wtf --app web
relish dashboard

The advantage is cluster-aware explanation in the same tool: placement refusal, missing evidence and network-path problems are surfaced explicitly. Coolify's advantage is fewer bespoke steps between repository, preview URL and database backup. Neither interface removes the need to test the application's actual behavior. Diagnostic evidence · preview lifecycle.

Application releases versus platform upgrades #

Coolify applications: eligible non-Compose deployments can start a replacement, wait for health and retain the old container if the new one fails. Compose uses its own reconciliation; published host ports and fixed container names also prevent overlap. A rollback selects a retained old image but uses current runtime settings and does not reverse database migrations. Replacement rules · rollback semantics.

Reliaburger applications: the leader advances a changed spec one node at a time after that node becomes healthy. Surge/unavailable limits are per node. The council retains successful versions for rollback across restarts; failed rollouts remain halted until a changed spec or rollback. Managed volumes force stop-first replacement. These rollout rules arrived in 0.2.1. Pinned rollout contract.

Coolify itself: Settings → Updates controls instance updates. They replace the control plane, not managed applications or operating systems; active deployments can fail during the update. Bun itself: compatible updates roll workers first and council members individually, with signatures and automatic crash-loop reversion. Protocol/state mismatches require a fresh cluster; a 0.2.1 cluster can't upgrade in place to 0.2.2. Coolify update boundary · Bun compatibility and upgrade rules.

Where Reliaburger fits #

Choose Reliaburger for an integrated cluster workflow: place replicas across nodes, inspect why an application is unhealthy, trace its network path and test a controlled failure with the same toolset. Our assessment is that this fits operators who value cluster behavior and evidence-rich diagnosis. Coolify fits teams whose priority is a self-service browser workflow for builds, previews and domains. Reliaburger diagnostics · controlled faults · Coolify workflow.

Coolify operates a web application with PostgreSQL and Redis alongside Docker and its proxy. Reliaburger embeds more functions, but remains a prototype with rootful/eBPF cluster requirements and no built-in ACME. The operational choice is between maintaining composed services and accepting a young integrated platform's constraints. Coolify services · Reliaburger status · TLS limits.

Backups need precision: current Coolify supports eligible application storage-mount archives as well as engine-aware dumps. Reliaburger provides Btrfs snapshots and separate council backups; a council backup excludes application volumes. None of those facts proves a successful restore of your database. Storage archives · volume snapshots · council recovery.
