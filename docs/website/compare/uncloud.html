Reliaburger and Uncloud

Reliaburger keeps reconciling application placement after deployment, with metrics, GitOps and failure diagnostics in the same toolchain. Uncloud offers a Compose workflow with WireGuard and automatic HTTPS. The key choice is how much ongoing cluster operation you want the platform to handle.

The verdict #

Two Reliaburger baselines. Installation examples fetch released 0.1.6. Unless labelled otherwise, capability comparisons inspect the unreleased release-0-2-1 integration branch at 32effd96. Its rollout fixes are implemented, but are not in that installer. Source presence is not release qualification. Deployment contract · Compatibility policy.

Where Reliaburger leads

Reliaburger continuously reconciles desired app placement and replaces eligible stateless replicas after node loss. It also brings a broader operational toolkit: metrics, alert rules, GitOps, network diagnosis and fault injection. Uncloud deliberately leaves failed-machine replacement and redeployment to the operator. Cluster behaviour · Included tools · Uncloud failure model.

Where Uncloud leads

Uncloud has the shorter documented path from an existing Compose application to several Docker hosts with private WireGuard networking and public HTTPS. Its Caddy integration provisions certificates, and its CLI can build and transfer images directly to machines. That is a practical advantage for a small web application. Architecture and workflow · Ingress.

We review Uncloud 0.21.0, not its nightly build. Neither system automatically makes local database data durable across node loss. Keep stateful storage and application replication in the decision, rather than treating surviving web replicas as proof of database availability. Volume support · Reliaburger data locality.

Install on machines you can reach #

Uncloud’s quickstart assumes an Ubuntu or Debian server with a public IP and key-based SSH, as root or a user with passwordless sudo. The CLI runs on your workstation. machine init installs Docker and the daemon unless told otherwise, configures the machine and deploys Caddy. Replace the example addresses below with your own hosts. Prerequisites and setup.

UNCLOUD · WORKSTATION AND TWO SERVERS
brew install psviderski/tap/uncloud
uc version
uc machine init --version v0.21.0 root@server-one
uc machine add --version v0.21.0 root@server-two
uc machine ls
RELIABURGER · STABLE LAPTOP CLUSTER
curl -fsSL https://reliaburger.com/install.sh | RELIABURGER_VERSION=v0.1.6 sh
relish nodes
relish council status

Commands: Uncloud CLI installation, init, add; Reliaburger stable quickstart. Homebrew tracks its current formula; check uc version, or obtain the pinned CLI from the 0.21.0 release.

These commands provision different things. Reliaburger’s installer creates a three-node cluster in managed Linux VMs, requiring approximately 8 GiB free memory and 15 GiB disk. That convenience is valuable for an isolated experiment. Deploying it onto existing servers is a separate procedure with runc, eBPF and firewall prerequisites. Uncloud begins with your own remote machines and supplies the overlay network. Laptop requirements · Existing servers · Uncloud network.

Deploy and inspect a web service #

For Uncloud, this small compose.yaml publishes Nginx through its managed HTTPS domain. It assumes the cluster’s DNS reservation and publicly reachable Caddy succeeded. A custom domain needs DNS pointing to suitable ingress machines. x-ports is an Uncloud extension, not a portable Compose field. Port extension · Publishing services.

UNCLOUD · COMPOSE.YAML
services:
  web:
    image: nginx:1.28-alpine
    deploy:
      replicas: 2
    x-ports:
      - 80/https

The corresponding Reliaburger application is a TOML app with image, port, replicas and an optional ingress block. HTTPS currently needs a supplied certificate or trust in the cluster CA, so this is not an equivalent automatic-public-certificate workflow. App specification · Ingress contract.

UNCLOUD · FROM THE COMPOSE DIRECTORY
uc deploy
uc ps
uc logs -f web
uc scale web 3
# Edit the image tag, then:
uc deploy
RELIABURGER · WITH A VALID WEB.TOML
relish lint web.toml
relish apply web.toml --dry-run
relish apply web.toml
relish inspect web
relish logs web
# Set replicas = 3, then:
relish apply web.toml

Commands: deploy, ps, logs, scale; Reliaburger deployment and logs. Uncloud asks you to approve its deployment plan; --yes opts into unattended execution.

Compose familiarity is a real benefit, but compatibility is a subset. In 0.21.0, custom networks, dns and labels are unsupported; ports and dependencies have restrictions. All containers share the cluster network. Review the support matrix before moving a Compose stack, especially if its security model depends on separate networks. Reliaburger does not accept Compose; its Kubernetes importer has its own documented losses. Exact Compose matrix · Accepted manifest formats · Kubernetes translation.

Updates, partial failures and daemon versions #

Application update: uc deploy replaces containers sequentially with health monitoring. Its default start-first order changes to stop-first for host-port conflicts and a single replica using a volume. A failed replacement is stopped; for stop-first, the old container restarts. Earlier successful replacements remain on the new version. Re-running deploy retries the remaining work. This is automatic recovery of the failed replacement, not atomic rollback of the whole service. 0.21.0 rolling deployment contract.

The reviewed Reliaburger branch also gates rollout progress on health, releases node shares in sequence and records RolloutFailed rather than repeatedly retrying a bad specification. It keeps previous successful versions for explicit relish rollback web. Managed-volume apps still roll stop-first. These are branch capabilities; the stable installer predates the rollout safety fixes. Reviewed rollout implementation.

Orchestrator update: upgrading uc on your laptop, upgrading uncloudd on servers, and changing Caddy are separate operations. brew upgrade uncloud updates the CLI. The daemon installer selects UNCLOUD_VERSION and replaces a differing installed binary; inspect the release and apply it on each host. uc caddy deploy updates the proxy. Despite its name, uc machine update changes machine metadata and endpoints, not daemon software. CLI updates · Daemon installer · Caddy updates · Machine metadata.

Reliaburger provides cluster-wide signed binary upgrade planning and execution, with compatibility checks. However, pre-1.0 format changes require cluster recreation; a rolling upgrade command does not override that policy. We found no basis for claiming either project offers an effortless upgrade across every future version. Upgrade operations · Compatibility boundary.

Where Reliaburger fits #

Keep operating after the deploy. Reliaburger combines desired-state repair with GitOps, metrics, a registry and fault rehearsal. Its diagnostic commands let you investigate placement and service paths through the same CLI used to deploy. That is a concrete advantage when ongoing cluster operation matters alongside the initial release. Plan around node-local storage, supplied public certificates and the documented pre-1.0 compatibility limits. Integrated features · Diagnostics · Storage · TLS · Release policy.

Choose Uncloud for Compose-oriented web deployment on a few machines, particularly when WireGuard and automatic HTTPS remove work you would otherwise do yourself. Its execution plans make changes visible. Its imperative model also leaves you responsible for deciding when to repair placement after machine loss. Those properties belong together. Design choices · Failure model.

Learning curve, our assessment: Docker users should recognise more of Uncloud’s service, image and volume vocabulary. Reliaburger asks them to learn TOML apps and council behaviour, then gives them a common place to inspect and test the platform. We have no timed onboarding study, so this is a qualitative judgement about concepts and steps, not a measured productivity claim. Uncloud concepts · Reliaburger concepts.

Both projects use Apache-2.0. Uncloud licence · Reliaburger licence.

Evidence and limits #

Uncloud citations are pinned to v0.21.0; Reliaburger implementation citations to 32effd96, with installation instructions labelled 0.1.6. We prioritised the versioned deployment guide and code over the older README sentence saying automatic rollback was still forthcoming.

This is a documentation and source comparison. No matched performance, outage-recovery or penetration test was run. A WireGuard mesh is a connectivity mechanism, not evidence by itself of tenant isolation; a rolling deployment feature is not proof that every stateful application can update without downtime.
