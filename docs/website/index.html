01 /

Try it in five minutes

Arrives with 0.1.0

This is the tour 0.1.0 has to pass before we publish it. Until the signed release is out, the install line stops with a release-not-published message. You’ll need macOS, or Linux with QEMU and KVM, plus about 8 GiB of free memory and 15 GiB of disk.

  1. curl -fsSL https://reliaburger.com/install.sh | sh

    Installs relish, then builds a three-node cluster in Linux VMs on your laptop. It checks every download against a pinned digest, and it’s the only step that takes minutes.

  2. relish apply -f https://reliaburger.com/demo/podinfo.yaml

    A real Kubernetes app: podinfo’s frontend, backend and Redis cache. Relish converts the YAML as it applies it and prints a report of anything it had to change.

  3. relish status

    Three frontend replicas, spread over three nodes. The scheduler did that, not you.

  4. open http://podinfo.localhost:18080

    Or paste the address into a browser. The request comes in through the built-in ingress, and the page shows which replica answered.

  5. relish logs frontend --since 1m

    Logs from every replica on every node, in one stream. No log shipper to install.

  6. relish dashboard

    Live CPU and memory charts in your browser, over the CLI’s own authenticated connection. Ctrl-C closes it; the cluster keeps running.

  7. relish fault kill frontend --count 1 --acknowledge

    Break it on purpose. Fault injection is built in, and on a laptop cluster it’s switched on.

  8. relish status

    Run it again. The killed replica is back, because the node agent restarts what should be running.

  9. relish local stop NODE

    Now lose a whole machine. Use the name of the third node from relish status.

  10. relish status

    The replicas that lived there come back on the two survivors.

  11. relish wtf

    One screen on what just happened and what still needs attention. It’s what you’d run first in a real incident.

Finished? Remove the cluster, then Relish itself:

relish local destroy --yes
relish uninstall

02 /

Run it from source

Start with a local process. No container runtime required.

You’ll need Rust and the build tools for your platform. This example runs hello under the built-in ProcessGrill runtime; it doesn’t create an isolated container or a multi-node cluster.

For real OCI containers, use runc on Linux. On macOS, the managed laptop quickstart uses Linux VMs. Direct Apple Container is deferred beyond 0.1.0.

Build requirements & runtime setup ↗
LOCAL DEVELOPMENT sh
# Terminal 1 · build and start the agent
git clone https://github.com/reliaburger/reliaburger
cd reliaburger
cargo build --bins
target/debug/bun --runtime process

# Terminal 2 · from the same checkout
target/debug/relish apply \
  examples/phase-1/proc-first-run.toml
target/debug/relish status
target/debug/relish
Web dashboard: http://127.0.0.1:9117/
